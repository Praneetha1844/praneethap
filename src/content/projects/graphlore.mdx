> **Status:** the implementation and its test suite are included, but they have not yet been run in a clean environment, and benchmarks are not yet published. This page describes the design and scope; the repository README is the source of truth for the exact behaviour.

## Problem

Some questions cannot be answered from a single passage. "Which teams use a service that depends on this library?" needs several facts joined together. Searching text finds passages; it does not follow relationships.

Graphlore builds a **knowledge graph** from documents and answers **multi-hop questions** by following relations between entities.

## Approach

1. **Extract** entities and the relations between them from documents.
2. **Build** a graph that links those entities.
3. **Answer** a question by finding a path of relations that connects what it asks about, and return the path as evidence.

Returning the path matters: a reader can check each hop against the source instead of trusting a single generated sentence.

## Design considerations

- **Provenance.** Every edge must cite a stored chunk of text, so each hop can be checked against its source.
- **Typed by an ontology.** Entity types and relations are declared up front, and facts that do not fit are rejected.
- **Abstain over guess.** A question with no supporting path gets "no supported answer".
- **Errors compound.** A wrong relation early in a path produces a confidently wrong answer, so extraction quality and evaluation matter more than the question-answering step.
- **Evaluation first.** The project is designed around measuring answer correctness on a labelled question set rather than judging by examples.

## Limitations

- Entity and relation extraction is imperfect and limits everything downstream.
- No evaluation results are published yet. Accuracy will be reported only after it has been measured on a documented question set.
- It is a research-style prototype, not a product.

## Roadmap

- Publish an evaluation on an open dataset, with the method and results written up.
- Derive edge confidence from extractor agreement and calibrate it on a labelled sample.
- Passive-voice patterns and simple coreference in the rule-based extractor.
